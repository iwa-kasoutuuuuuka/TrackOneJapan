# TrackOneJapan サーバー構築手順（Windows 11）

設計の考え方は [03_サーバー設計.md](03_サーバー設計.md) を参照してください。
所要時間: 約1時間（回線確認・ルーター設定を含む）

---

## 手順0: 回線がポート転送できるか確認する（最重要）

発信機からの接続を受けるには、ルーターでポート転送ができる回線である必要があります。

1. 本番 PC で PowerShell を開き、次を実行（インターネットから見た自宅の IP が表示されます）
   ```powershell
   (Invoke-WebRequest -UseBasicParsing https://api.ipify.org).Content
   ```
2. ルーターの管理画面（例: `http://192.168.1.1`）を開き、「WAN 側 IP アドレス」「接続方式」を確認
3. 判定

| 結果 | 判定 |
|---|---|
| 1 と 2 の IP が同じ、接続方式が PPPoE | ◎ そのまま進める |
| 接続方式が「v6プラス」「MAP-E」「OCN バーチャルコネクト」 | △ ルーターに表示される「利用可能ポート」の中から1つ選んで使う |
| 接続方式が「DS-Lite」「transix」「クロスパス」、または IP が `100.64.` 〜 `100.127.` で始まる | × ポート転送不可。設計書の「代替案」が必要 |
| 1 と 2 の IP が違う（上記以外） | × ルーターの外側にもう1台ルーターがある（二重ルーター）可能性。プロバイダのルーターを確認 |

## 手順1: 本番 PC の準備

1. **BIOS/UEFI 設定**: 「Restore on AC Power Loss」（AC 電源復帰時の動作）を **Power On** にする
   （メーカーにより名称が異なります。停電から復旧したとき自動で起動するための設定）
2. **固定 IP**: ルーターの管理画面で、本番 PC に毎回同じ LAN 内 IP が割り当たるよう設定（DHCP 予約）
3. **有線 LAN** で接続（Wi-Fi より安定）
4. Windows Update を最新にしておく

---

## 手順2: DuckDNS（無料ドメイン）を取得

1. https://www.duckdns.org にアクセスし、GitHub か Google アカウントでログイン
2. 「sub domain」に好きな名前（例: `myhome-tracker`）を入力して「add domain」
   → `myhome-tracker.duckdns.org` が使えるようになります
3. 画面上部の **token**（長い英数字）を控える。他人に見せないこと

---

## 手順3: スクリプトの入手と設定

1. GitHub から一式をダウンロード
   - https://github.com/iwa-kasoutuuuuuka/TrackOneJapan →「Code」→「Download ZIP」→ 展開
   - または `git clone https://github.com/iwa-kasoutuuuuuka/TrackOneJapan.git`
2. `server\windows\config.example.psd1` を同じフォルダに **`config.psd1`** という名前でコピー
3. `config.psd1` をメモ帳で開いて編集
   - `DuckDnsDomain = 'myhome-tracker'`（手順2で決めた名前。`.duckdns.org` は付けない）
   - MAP-E 回線の場合でも `Gt06Port = 5023` のままで OK（外部ポートはルーター側で決める）
   - 外付けドライブ等にもバックアップしたい場合は `BackupCopyTo = 'D:\TrackOneBackup'`
     （バックアップには全データが入るので、他の人が読めない場所にする）

> この `config.psd1` が使われるのは**初回のインストールだけ**です。初回に `C:\TrackOneServer\config\config.psd1` へコピーされ、
> 2 回目以降の install.ps1 はインストール済みの設定を使います（上書きしません）。
> リポジトリ側の設定で上書きしたいときだけ `-ConfigPath .\config.psd1` を付けて実行します。

---

## 手順4: インストール

1. スタートメニューで「PowerShell」を右クリック →「管理者として実行」
2. 展開したフォルダへ移動して実行
   ```powershell
   cd C:\Users\<ユーザー名>\Downloads\TrackOneJapan-main\server\windows
   powershell -ExecutionPolicy Bypass -File .\install.ps1
   ```
3. 途中で DuckDNS のトークンを聞かれたら、手順2で控えたものを貼り付け
4. 「=== インストール完了 ===」と表示されれば成功

> 実行前に内容だけ確認したい場合: `powershell -ExecutionPolicy Bypass -File .\install.ps1 -DryRun`（何も変更しません）

インストールされるもの:
- PostgreSQL 17（サービス名 `postgresql-x64-17`）
- Traccar（サービス名 `traccar`、`C:\Program Files\Traccar`）
- Tailscale
- `C:\TrackOneServer`（設定・スクリプト・バックアップ・ログ）
  - アクセス権は管理者と SYSTEM だけに限定されます（一般ユーザーはスクリプト・設定・アイコンを読めるだけ。
    バックアップ・パスワード・状態ファイルは読めません。ログはインストールした人も読めます）
- タスクスケジューラの `\TrackOne\` フォルダに 3 つのタスク（HealthCheck / Backup / DuckDNS）

> PostgreSQL のインストール時に使った初期パスワードは winget のログに残るため、install.ps1 がインストール直後に
> 別のパスワードへ変更します（ログの場所も表示されるので、不要なら削除してください）。

## 手順5: Traccar の初期設定

1. デスクトップの「TrackOne 管理画面」（オリジナルアイコンのショートカット）を開く
   （または本番 PC のブラウザで http://localhost:8082）
2. 最初は自動で「登録」画面が開くので、アカウントを作成（**最初のユーザーが管理者**になります）
   - 2 人目以降は自由に登録できない設定が初期状態です（Traccar 6.16 で確認済み）
   - 家族用のアカウントは、管理者が「設定」→「ユーザー」から追加します
   - 画面はブラウザの言語に合わせて日本語で表示されます（ログイン画面右上でも切替可）
3. 地図画面左上の「＋」で発信機を登録
   - 名前: 好きな名前（例: 「車」）
   - 識別子: 発信機の **IMEI**（15桁。本体ラベルか TrackerOne の端末詳細に記載）

## 手順6: スマホアプリ用の HTTPS 公開（Tailscale Funnel）

1. https://tailscale.com で無料アカウントを作成（Google / Microsoft / GitHub アカウントで可）
2. 管理者 PowerShell で本番 PC を Tailscale にログイン
   ```powershell
   & "$env:ProgramFiles\Tailscale\tailscale.exe" up --unattended
   ```
   ブラウザが開くのでログインを承認
   （`--unattended` を付けないと、停電や Windows Update で再起動したあと、誰かが Windows にログインするまで
   Tailscale がつながらず、アプリから見られなくなります。付け忘れた場合は、付けてもう一度実行すれば OK）
3. Funnel（インターネットへの HTTPS 公開）を有効化
   ```powershell
   & "$env:ProgramFiles\Tailscale\tailscale.exe" funnel --bg http://127.0.0.1:8082
   ```
   初回は「Funnel を有効にする」ための URL が表示されるので、開いて承認し、もう一度実行
4. 表示された `https://<PC名>.<tailnet名>.ts.net` を控える
   → スマホのブラウザや、今後作る日本語アプリからこの URL でアクセスします

確認: スマホの Wi-Fi を切り、モバイル回線でこの URL を開いてログイン画面が出れば成功

## 手順7: ルーターのポート転送

ルーターの管理画面で「ポート転送」「ポートマッピング」「静的 IP マスカレード」などの項目を開き、次を追加します。

| 項目 | 値 |
|---|---|
| プロトコル | TCP |
| 外部（WAN 側）ポート | PPPoE: `5023` ／ MAP-E: 利用可能ポートの中から1つ（例: `12345`） |
| 転送先 IP | 本番 PC の LAN 内 IP（手順1で固定したもの） |
| 転送先ポート | `5023` |

確認（スマホのモバイル回線で、ポート確認サイトなどから `<ドメイン>.duckdns.org` の外部ポートが「開いている」と出れば OK）

## 手順8: 発信機の接続先を変更（SMS）

> **注意:** 切り替えると TrackerOne アプリでは位置が見られなくなります。
> 先に TrackerOne の「サーバー切替」画面で**元の設定文**を控えておけば、いつでも戻せます。

1. TrackerOne アプリの「サーバー切替」画面を開き、表示される SMS の文面の形式を確認する（送信はしない）
2. その形式のドメイン（またはIP）とポートを書き換えて、**発信機の SIM の電話番号**あてに SMS を送る

GT06 系の発信機で一般的な形式（機種によって異なるため、必ず手順8-1 で確認した形式を優先）:

```
SERVER,1,myhome-tracker.duckdns.org,5023,0#
```
- `1` = ドメイン指定（`0` だと IP 指定）
- `5023` = 手順7の **外部ポート**（MAP-E の場合は選んだポート番号）
- 機種によっては先頭にパスワードが必要（例: `SERVER,666666,1,...`）

3. 発信機から返信 SMS（`OK` など）が来れば受付完了
4. 数分以内に Traccar の画面で端末が「オンライン」になり、地図に位置が表示されれば成功

うまくいかない場合:
- Traccar のログ `C:\Program Files\Traccar\logs\tracker-server.log` に `gt06` の行と IMEI が出ているか確認
  - 出ていない → ポート転送・DuckDNS・SMS の設定を確認
  - `Unknown device` と出る → 手順5の IMEI の登録ミス
  - 接続はあるが位置が 0 → 屋外に置いて GPS を受信させる（停車中は位置を送らない機種もある）

## 日常の運用

スクリプトはすべて **管理者 PowerShell** で、`powershell -ExecutionPolicy Bypass -File <スクリプト>` の形で実行します
（`C:\TrackOneServer\scripts\backup.ps1` のように直接打つと、実行ポリシーで止まることがあります）。
以下の表では `PS -File` と略します。

| やりたいこと | 方法 |
|---|---|
| 状態を確認 | `C:\TrackOneServer\logs\healthcheck-YYYYMM.log`（インストールした人は管理者権限なしでも読めます） |
| 手動バックアップ | `PS -File C:\TrackOneServer\scripts\backup.ps1` |
| バックアップから復元 | `PS -File C:\TrackOneServer\scripts\restore.ps1 -BackupFile C:\TrackOneServer\backup\traccar-YYYYMMDD-HHMMSS.dump`（ファイルの指定を推奨。省略するとファイル名の日時が最新のものを使う） |
| Traccar を更新 | `PS -File C:\TrackOneServer\scripts\update-traccar.ps1 -Version 6.17.0`（`config.psd1` の `TraccarVersion` も自動で書き換わる） |
| 設定を変更 | `C:\TrackOneServer\config\config.psd1` を**管理者として開いたメモ帳**で編集し、`PS -File C:\TrackOneServer\scripts\install.ps1` を実行（テスト PC は `-TestMode` を付ける） |
| DB のパスワードを変更 | `PS -File C:\TrackOneServer\scripts\rotate-db-password.ps1`（Traccar が 1 分ほど止まる） |
| サービスの再起動 | `Restart-Service traccar` |

補足:
- 復元・更新・インストールの実行中は、死活監視が Traccar を勝手に起動しないよう `C:\TrackOneServer\state\maintenance.flag` が置かれます
  （終わると消えます。途中で強制終了して残っても、2 時間たてば無視されます）。
- 復元に失敗した場合、Traccar は**止めたまま**になり、`state\restore-failed.flag` が置かれます（空のデータで動き出さないように）。
  表示される案内に従って、別のバックアップか「復元前のバックアップ」を指定して `restore.ps1` をやり直してください。
- インストール済みの Traccar より古い `TraccarVersion` で install.ps1 を実行すると、データベースを守るため中止します
  （どうしても戻す場合は `-AllowDowngrade`。入れ替え前に自動でバックアップします）。
- ログの保存期間: スクリプトのログ 90 日、Traccar のログ（`C:\Program Files\Traccar\logs\tracker-server.log.YYYYMMDD`）30 日、
  PostgreSQL のログ（`C:\Program Files\PostgreSQL\17\data\log`）30 日。毎日のバックアップのときに古いものを削除します。

### 以前のバージョンのスクリプトでインストールした PC（パスワードの後始末）
以前の install.ps1 では、PostgreSQL の postgres パスワードが winget のログに残り、バックアップ（DB パスワード入りの `traccar-*.xml`）も
一般ユーザーが読める状態でした。最新のスクリプトで一度だけ次を実行してください。
1. `PS -File <リポジトリ>\server\windows\install.ps1`（アクセス権の修正。テスト PC は `-TestMode`）
2. `PS -File C:\TrackOneServer\scripts\rotate-db-password.ps1 -RemoveLeakedLogs`
   （postgres と Traccar 用ユーザーのパスワードを変更し、古いパスワードが書かれたログを削除）
3. 手で消す場合のログの場所:
   `%LOCALAPPDATA%\Packages\Microsoft.DesktopAppInstaller_8wekyb3d8bbwe\LocalState\DiagOutputDir\WinGet-*.log`
   （PostgreSQL をインストールしたユーザーのもの。中に `--superpassword` と書かれたファイル）
   ```powershell
   Get-ChildItem "$env:LOCALAPPDATA\Packages\Microsoft.DesktopAppInstaller_8wekyb3d8bbwe\LocalState\DiagOutputDir\WinGet-*.log" |
       Where-Object { Select-String -Path $_.FullName -Pattern '--superpassword' -SimpleMatch -Quiet } | Remove-Item
   ```

### PC を買い替える・移設するとき
1. 旧 PC で `PS -File C:\TrackOneServer\scripts\backup.ps1` を実行し、次の 2 つを USB メモリ等にコピー（管理者権限が必要）
   - `C:\TrackOneServer\backup` の最新の `traccar-YYYYMMDD-HHMMSS.dump`
   - `C:\TrackOneServer\secrets` フォルダごと（DB パスワード・DuckDNS トークン。**他人に渡さない**。移設後は USB から削除）
   ```powershell
   # 管理者 PowerShell で（E: は USB メモリ）
   Copy-Item C:\TrackOneServer\backup\traccar-YYYYMMDD-HHMMSS.dump E:\
   Copy-Item C:\TrackOneServer\secrets E:\secrets -Recurse
   ```
2. 新 PC で手順1〜3を実施し、手順4の**前に** `C:\TrackOneServer\secrets` を作って、旧 PC の secrets の中身を入れる
   （install.ps1 がそのパスワードとトークンを使い、フォルダのアクセス権も管理者のみに直します）
3. 新 PC で手順4（install.ps1）を実施
4. 新 PC で、コピーした `.dump` を指定して復元
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\TrackOneServer\scripts\restore.ps1 -BackupFile D:\traccar-YYYYMMDD-HHMMSS.dump
   ```
5. ルーターのポート転送先を新 PC の IP に変更（DuckDNS は自動で追従）

## テスト用 PC で試す場合

常時起動しない PC での動作確認用です。電源設定・Windows Update・ファイアウォール・タスク・Tailscale は変更しません
（`C:\TrackOneServer` のアクセス権の設定は行います）。設定を変えて再実行するときも `-TestMode` を付けてください。

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -TestMode
```

発信機なしで位置の受信を試す（OsmAnd 方式で、PC 自身から送信）:
1. Traccar の画面で、識別子 `123456` の端末を登録
2. PowerShell で送信
   ```powershell
   Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:5055/?id=123456&lat=35.681236&lon=139.767125&speed=0&batt=80"
   ```
3. 地図の東京駅付近に端末が表示されれば成功

### テスト PC から削除する
1. 「設定」→「アプリ」から **Traccar**、**PostgreSQL 17** をアンインストール
2. `C:\TrackOneServer` と `C:\Program Files\PostgreSQL` のデータフォルダを削除（不要な場合）
